## Consequential findings in the first seal

1. **P1 — outcome completion is counted without decision linkage.** `runtime_v2/operations.py:302`–314 counts every hash-valid `outcomes/*.json`. It does not require one unique expected `decision_session`, matching trial/release, matching `decision_sha256`, exact universe, correct entry/endpoint dates, outcome maturity, or returns recomputed from the bound snapshot. `mature()` at lines257–259 also treats any hash-valid existing file as complete. Unrelated/duplicate receipts can therefore inflate label-completion status. Remedy: one strict outcome validator reused by maturation and status, with invalid/unbound/premature/duplicate outcome regression tests.

2. **P1 — receipt audit checks transport manifests without checking their artifact bytes.** `operations.py:111`–115 checks the snapshot-manifest digest and model-manifest digest but not referenced Parquet, raw response or `model.joblib` bytes. Altering an input/model binary while retaining its manifest can leave it counted as valid evidence. Remedy: validate every referenced artifact digest during receipt audit, including old daily refit models, and prove altered bytes are rejected before any state-opening path can create/reset account storage.

3. **P1 — the common manual daily path bypasses the durable halt.** `operations.py:399` enforces `halt.json` only in `tick()`. `daily()`/`_daily()` at lines137–157 does not enforce it; the public CLI calls this function directly at `scripts/collector_v2.py:21`. Corrected provider data can consequently permit a manual within-window commit after a deterministic halt that the scheduler would honor. Remedy: enforce halt in the common daily path, with a defined exception only for genuinely idempotent validation/recovery, and test direct daily invocation under halt.

4. **P1 — copied backup is not a relocatable executable recovery.** `operations.py:319`–347 copies data and validates hashes/SQLite integrity. Immutable plans/results retain absolute snapshot and model paths from `operations.py:206` and `policy.py:75`. A copy restored to another workspace still resolves the original directory; if the original is lost, receipt validation and resumed fitting fail. The original operations document instructed a separate-directory restore, while its test only read the copied receipt. Remedy: either implement a provenance-preserving relocation resolver or explicitly support staged, archived, atomic restoration to the exact original path and test status plus the next decision with the original unavailable. The collector owner selected the latter contract.

5. **P1 — partial model-refit restart can combine different provider vintages.** In `policy.py:61`–75 an already-written model is reused solely by fitting date. If a crash occurs before the plan is saved, `_daily()` at lines197–205 downloads a new snapshot. Revised historical bars can then coexist with models already fitted from the earlier snapshot, although the final plan binds only the newer snapshot. Remedy: freeze and persist the selected snapshot before model generation, or verify a model-associated digest of the exact fitting input before reuse. Preserve rather than overwrite prior completed models, and test a partial-refit crash followed by changed provider history.

These are local evidence/recovery defects, not evidence of external order exposure. Broker orders remain disabled. The prospective period has not started, so these can be repaired and qualified under a new registered seal before observations begin.
